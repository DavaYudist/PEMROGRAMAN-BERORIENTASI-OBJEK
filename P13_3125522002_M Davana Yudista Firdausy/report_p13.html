A. DASAR TEORI SINGKAT

Membangun aplikasi tingkat produksi menuntut integrasi yang harmonis antara seluruh komponen yang telah dipelajari pada modul-modul sebelumnya (OOP, Collection, Exception Handling, dan File Persistence) ke dalam antarmuka interaktif yang mudah dipahami oleh pengguna. Pada Modul 13, integrasi ini diwujudkan melalui antarmuka konsol berbasis menu dengan berpedoman pada prinsip-prinsip rekayasa perangkat lunak modern:

  • Pemisahan Tanggung Jawab (Separation of Concerns): Lapisan antarmuka pengguna (kelas Main) hanya bertanggung jawab memandu input/output (membaca prompt Scanner, menampilkan pesan keberhasilan/kegagalan), sedangkan aturan bisnis, penegakan keunikan, dan integritas data sepenuhnya didelegasikan kepada kelas domain Perpustakaan.
  • Dekomposisi Metode Modular: Menghindari metode main() raksasa (anti-pattern God Method) dengan memecah setiap opsi transaksi ke dalam sub-metode terfokus seperti menuTambah, menuCari, menuHapus, menuSimpan, dan menuMuat.
  • Pelacakan Status Perubahan (Dirty State Tracking): Mengelola flag boolean berubah untuk memantau apakah ada data di memori utama yang telah termutasi sejak operasi simpan terakhir. Hal ini krusial untuk mencegah pengguna kehilangan data secara tidak sengaja.
  • Penjaga Keluar dan Muat Ulang (Guarded Exit and Reload): Jika pengguna memilih opsi Keluar (0) atau Muat Ulang (6) sementara kondisi berubah == true, sistem wajib menginterupsi dengan dialog konfirmasi eksplisit ("Perubahan belum disimpan. Abaikan perubahan? Ketik YA: ").
  • Penanganan Kesalahan Tangguh (Graceful Degradation): Seluruh eksepsi dari lapisan bawah (seperti IllegalArgumentException atau IOException) ditangkap secara anggun pada lapisan menu sehingga aplikasi tidak berhenti mendadak (crash).

E. EVALUASI DAN JAWABAN PERTANYAAN MODUL 13

1. Mengapa logika keunikan kode buku tetap harus berada di class Perpustakaan, bukan di menu?
Jawaban: Berdasarkan prinsip Single Responsibility Principle (SRP) dan High Cohesion, keunikan kode buku adalah aturan bisnis inti (Domain Invariant), bukan urusan presentasi antarmuka. Jika logika tersebut diletakkan di menu, maka ketika aplikasi di masa mendatang dikembangkan dengan antarmuka lain (seperti JavaFX GUI, REST API Web Service, atau skrip batch), aturan keunikan tersebut harus ditulis ulang dan rentan terlewat. Menjaga logika di dalam Perpustakaan memastikan aturan domain berlaku konsisten di saluran akses manapun.
2. Mengapa variabel 'berubah' hanya boleh di-reset ke 'false' setelah operasi simpan berhasil?
Jawaban: Variabel berubah merepresentasikan divergensi (perbedaan) antara state koleksi yang berada di memori utama (RAM) dengan state rekaman fisik yang ada di penyimpanan sekunder (disk). Selama data di disk belum secara nyata berhasil diperbarui oleh sistem berkas (misal karena kegagalan izin akses atau disk penuh), divergensi tersebut masih terjadi. Me-reset berubah sebelum verifikasi tulis fisik berhasil akan memberikan ilusi keliru bahwa data telah aman, sehingga pengguna berisiko keluar dari program dan kehilangan datanya.
3. Apa konsekuensinya jika 'berubah' langsung di-reset sebelum operasi simpan dipastikan berhasil?
Jawaban: Konsekuensinya adalah terjadinya silent data loss (kehilangan data tanpa peringatan). Jika simpan gagal karena eksepsi I/O tetapi flag berubah terlanjur disetel ke false, maka saat pengguna kemudian menekan menu 0 (Keluar), aplikasi akan langsung menutup diri tanpa memicu dialog konfirmasi penjaga. Akibatnya, seluruh pekerjaan penambahan atau pembaruan yang baru saja dilakukan pengguna akan lenyap seketika tanpa ada peluang untuk melakukan perbaikan.
4. Mengapa pengujian seluruh alur aplikasi (tambah, cari, simpan, muat ulang) penting sebelum aplikasi dianggap selesai?
Jawaban: Pengujian unit parsial hanya membuktikan bahwa metode bekerja secara individual pada kondisi ideal. Namun dalam kenyataan, bug seringkali muncul pada titik integrasi (antarmuka antar-komponen) dan transisi state jangka panjang, seperti kegagalan sinkronisasi flag, kebocoran referensi, efek samping pemuatan berkas yang merusak koleksi, atau parsing Scanner yang tersangkut oleh karakter newline. Pengujian alur end-to-end memastikan seluruh siklus hidup aplikasi bekerja secara terpadu, stabil, dan andal bagi pengguna akhir.
