2. DASAR TEORI SINGKAT

Class Diagram merupakan diagram struktural UML yang digunakan untuk memodelkan struktur statis suatu sistem berorientasi objek. Komponen utama diagram mencakup nama class, atribut, method, serta relasi antarclass.

  • Visibilitas Member: Simbol + merepresentasikan akses public, simbol - merepresentasikan akses private (enkapsulasi), dan simbol # merepresentasikan protected.
  • Prinsip Fundamental: UML merupakan rancangan (blueprint), sedangkan source code merupakan bentuk implementasinya. Keduanya harus konsisten secara struktural maupun semantik.
  • Tanggung Jawab Class (Single Responsibility): Setiap class wajib memiliki behavior spesifik dan validasi state yang relevan, tidak sekadar pembungkus getter/setter pasif.

5. JAWABAN PERTANYAAN EVALUASI PRAKTIKUM (MODUL 9 HALAMAN 7)

Berikut adalah jawaban lengkap dan mendalam atas 5 pertanyaan evaluasi yang tercantum pada panduan Modul 9:

1. Apa perbedaan class pada UML dan object pada program?

Jawaban: Class pada UML merupakan cetak biru konseptual (*blueprint/structural specification*) yang mendefinisikan struktur data (atribut), perilaku (method), visibilitas, serta relasi yang akan dimiliki oleh suatu tipe entitas tanpa mengalokasikan memori fisik. Sedangkan object pada program merupakan wujud nyata (*instance*) dari class yang telah dialokasikan pada memori komputer (*heap memory*) pada saat runtime, memiliki identitas mandiri, serta menyimpan state data aktual yang nilainya dapat berubah selama program dieksekusi.

2. Bagaimana association pada UML diterapkan dalam Java?

Jawaban: Asosiasi pada UML diterapkan dalam bahasa Java dengan cara menyertakan referensi objek class lain sebagai atribut (field/instance variable) di dalam class yang membutuhkan. Dalam implementasi proyek ini:

  • Relasi Agregasi antara PerusahaanRental dan Kendaraan diterapkan dalam bentuk atribut koleksi private List<Kendaraan> daftarArmada;.
  • Objek-objek Kendaraan dibuat secara independen di luar, kemudian dimasukkan ke dalam perusahaan rental melalui method registerArmada(Kendaraan k).

3. Mengapa attribute sebaiknya tidak seluruhnya public?

Jawaban: Attribute sebaiknya tidak dibuat public demi menegakkan pilar Enkapsulasi (*Information Hiding*) dan melindungi integritas state data internal objek. Jika attribute bersifat public, kode eksternal dapat mengubah data secara sembarangan tanpa validasi (misalnya mengisi kapasitas baterai dengan nilai negatif -50% atau koordinat yang tidak masuk akal). Dengan menerapkan visibilitas private atau protected, setiap perubahan data wajib melalui method mutator (setter/action method) yang dilengkapi aturan validasi ketat (*domain defense*).

4. Apakah source code proyek sudah konsisten dengan UML?

Jawaban: Ya, source code proyek sudah konsisten 100% dengan UML Class Diagram yang dirancang. Seluruh nama class, hierarki pewarisan (Kendaraan ← MobilReguler, MobilVIP), implementasi antarmuka (implements PelacakGPS), atribut enkapsulasi (platNomor, merk, baterai, lat, lng, suhuKabin), method perhitungan dan telemetri, serta asosiasi agregasi telah diterjemahkan secara presisi ke dalam sintaksis Java tanpa adanya perbedaan nama maupun tipe data.

5. Class mana yang memiliki responsibility paling besar dalam proyek Anda?

Jawaban: Class yang memiliki responsibility paling besar dalam domain logika bisnis berorientasi objek adalah PerusahaanRental, karena bertindak sebagai agregator utama (*Information Expert*) yang mengelola seluruh siklus hidup koleksi armada, mengorkestrasi perubahan status sewa, menghitung ringkasan statistik bisnis, serta mengonversi heterogenitas armada menjadi representasi JSON. Di sisi infrastruktur runtime, Main memiliki tanggung jawab mengorkestrasi server HTTP, menangani permintaan rute web, dan menjalankan timer pembaruan telemetri GPS secara periodik.

Evaluasi Sprint Retrospective

  • Lesson Learned: Menerjemahkan diagram UML ke kode program menjadi jauh lebih mudah, terstruktur, dan minim bug ketika arsitektur antarclass didefinisikan secara matang sejak awal.
  • Rencana Pengembangan: Mengembangkan lapisan penyimpanan data menggunakan database SQL persisten serta mengintegrasikan komunikasi dua arah (*bidirectional*) via WebSocket.
